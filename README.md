# maimai-nfc-queue

舞萌机厅排队的最小验证：读卡器读交通联合卡的公开卡号，墨水屏显示队伍。
刷一次加入队尾；已在队列里的卡再刷一次进入“待确认退出”，5 秒内再刷才真的退出。

队列存在 ESP32 内部闪存里，断电后还在。不写卡，不读余额和乘车记录，不保存完整卡号。

## 现场怎么用

| 动作 | 结果 |
| --- | --- |
| 刷不在队列里的卡 | 加入队尾，屏幕提示 `JOINED #n` |
| 刷已在队列里的卡 | 进入待确认，屏幕把那一行反色，提示 `#n TAP AGAIN TO LEAVE` |
| 5 秒内再刷同一张 | 退出队列，提示 `LEFT #n` |
| 等 5 秒不刷 | 待确认自动取消，队列不变 |
| 长按按钮 3 秒 | 进入移人模式：选中的行反色，短按往下挪一格，再长按 3 秒把它移出队列 |
| 移人模式下 8 秒不动 | 自动退出模式 |

移人模式是给“排到中间的人走了”和“队首打完不走”准备的。选的起点永远是队首，
所以第一行反色时再长按一次，就等于原来的“移除队首”。

前 2 × 机台数 个位置算上机位，行尾显示已经打了多久；超过 15 分钟显示成 `>15m`，
只做提示，不自动踢人。

### 店员卡（可选）

设定之后，长按按钮要先刷一次店员卡，60 秒内有效。

1. 断电，按住按钮不放再上电，一直按到屏幕出现 `TAP STAFF CARD`（大约 3 秒）；
2. 刷想当店员卡的那张卡，屏幕提示 `STAFF CARD SET`。

想换一张就再走一次同样的流程。没设定店员卡时，长按按钮任何人都能用。

## 硬件

| 部件 | 型号 | 备注 |
| --- | --- | --- |
| 主控 | ESP32 DevKit（WROOM-32） | 用 3.3 V 逻辑 |
| 读卡 | PN532（I2C 模式） | 模块上的拨码开关要拨到 I2C |
| 屏幕 | 4.2 寸黑白墨水屏 400×300 | Waveshare 4.2" V2 / GoodDisplay GDEY042T81 |
| 按钮 | 任意常开轻触开关 | 一端接 GPIO27，一端接 GND |
| 供电 | 5 V / 1 A | 读卡瞬间电流会跳，别用太细的线 |

接线（引脚都在 `src/config.h` 里改）：

```
墨水屏 (SPI):  SCK=18  MOSI=23  CS=5   DC=17  RST=16  BUSY=4
PN532  (I2C):  SDA=21  SCL=22   IRQ=25 RST=26
按钮:          GPIO27 -> 按钮 -> GND（内部上拉）
```

旧批次的 4.2 寸屏驱动不同，把 `src/QueueDisplay.cpp` 里的 `GxEPD2_420_GDEY042T81`
换成 `GxEPD2_420`。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/TUnion.*` | 交通联合卡的 APDU 和 BER-TLV 解析，不含 Arduino 依赖 |
| `src/CardId.*` | 卡号 → 散列 + 显示用的末尾数字 |
| `src/QueueManager.*` | 排队状态机，时间由调用方传入，不含硬件依赖 |
| `src/QueueStorage.*` | 队列、盐、店员卡的持久化（NVS） |
| `src/CardReader.*` | PN532 封装，带总线自恢复 |
| `src/QueueDisplay.*` | 墨水屏排版，逐行比对后只刷新变化的区域 |
| `src/main.cpp` | 主循环、按钮交互、店员卡流程 |

## 存储格式

队列序列化成 `'Q' '2' count` + 每项 8 字节散列 + 8 字节数字 + 2 字节 CRC-16，
合计最多 389 字节。CRC 不对、长度不对、出现重复散列的内容一律当成损坏丢弃，
不会把坏数据读进队列。

旧固件写的 `'Q' '1'`（无校验、6 位数字）仍然能读，升级时队列不会丢；读进来之后
按新格式写回。数字宽度从 6 位扩到 8 位，是为了同批次发卡出现末尾重号时还能区分。

时间戳（入队时刻、上机时刻）不落盘，重启后从 0 重新算。真正的等待时长以现场为准，
这里只用来判断“停留过久”和“打了多久”。

## 隐私与边界

- 不写卡，不读余额、交易记录、身份信息。
- 队列里只有“加盐散列”和末尾 8 位数字，不存完整卡号。
- 散列是 64 位 FNV-1a，**不是密码学散列**。它的作用只是不把卡号明文留在闪存里；
  卡号本身有固定结构（发卡方标识、城市码），拿到盐之后枚举并不难。
  要防到那个程度，需要换 SipHash 之类的带密钥算法。
- 盐每台设备不同，所以两台设备的散列值不可比对。

## 已知限制

- 一支队伍只对应一列，没有分机台排队，也没有一个人多张卡的约束
  （一个人拿三张卡就能占三个位置）。
- 队列只在现场那块墨水屏上可见，排队的人没法远程查“我排第几”。
- 没有上机计时后的自动跳过，超过时限只做显示提示。
- 队列上限 24 张卡，多了会提示 `QUEUE FULL`。
- 移人模式会暂停读卡：进入模式期间刷的卡不会被处理。
